# レベル運用方針.md

## 目的
本書は、本プロジェクトにおけるレベル管理の方針を定義する文書である。  
PHASE_07 では、確認用の面データを `Main.gd` から分離し、`levels/` を正式なレベル配置場所として扱う。

---

## 背景
現状では確認用の面データが `Main.gd` 内に直接書かれている。  
この方式は初期試作には向いているが、以下の問題がある。

- `Main.gd` の責務が増える
- レベル追加時に Main を毎回編集する必要がある
- 確認用面と本番面を分けにくい
- Codex がレベル追加だけを安全に行いにくい
- テスト面の管理がしにくい

そのため、PHASE_07 ではレベルを外部化し、読み込み手順を整理する。

---

## 基本方針

### 1. Main.gd はレベル内容を直接持たない
`Main.gd` は司令塔に留める。  
レベル内容そのものは持たず、レベル ID やレベル配列の参照だけを扱う。

### 2. レベルは `levels/` 配下に置く
レベルデータは `levels/` ディレクトリ配下で管理する。  
少なくとも、確認用レベルと今後の本番レベルを分けられる構造にする。

### 3. LevelLoader.gd が読み込みの入口になる
レベル読込は `LevelLoader.gd` に集約する。  
`Main.gd` や `BoardView.gd` がファイル形式を直接解釈してはならない。

### 4. レベル選択情報とレベル内容を分離する
レベルの中身と、どの順で遊ぶか、どれが確認用か、といった管理情報は分ける。  
必要なら catalog ファイルを追加する。

---

## 目標

PHASE_07 の目標は以下である。

1. `Main.gd` から面データ直書きを撤去する
2. `levels/` からレベルを読み込めるようにする
3. レベル ID またはファイル名で切り替えられるようにする
4. 確認用レベルと本番候補レベルを分けられるようにする
5. 今後の追加ギミックでもレベル追加だけで確認できるようにする

---

## レベル分類

### 1. 確認用レベル
目的は仕様確認、回帰確認、個別挙動確認。  
短く、意図が明確であることを優先する。

例:
- basic_push
- basic_attract
- basic_repel
- chain_01
- conflict_priority
- conflict_simultaneous

### 2. プレイ用レベル
目的はゲームとして遊ぶこと。  
複数ルールを含んでよい。

PHASE_07 では、まず確認用レベルを優先する。  
本番向けの長いレベル群はその後でよい。


---

## 最小ファイル形式の方針

PHASE_07 では、既存の `LevelLoader.gd` が扱っている行文字列表現を外部ファイルに移せることを優先する。

最終的な本番形式は後続フェーズで見直してよい。

最低限、各レベルファイルは以下を表せる必要がある。

- レベル ID
- 表示名
- 目的
- 盤面の行データ

---

## 完了判定

PHASE_07 の完了条件は以下である。

1. `Main.gd` に面データ直書きが残っていない
2. `levels/` からレベルを読み込める
3. 確認用レベルを複数ファイルで管理できる
4. 次のレベル / 前のレベル / リセットが動く
5. 既存の確認面が外部化後も動作する
6. Main を触らずに新しい確認面を追加できる
7. 既存のプレイフローを壊していない
